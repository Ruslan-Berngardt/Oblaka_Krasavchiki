# Кадр / личная история кино

Сервис команды **Oblaka_Krasavchiki** для лабораторной 0. Каталог помогает выбрать фильм, а личная стена — сохранить впечатления, оценку и цитату после просмотра.

![Каталог фильмов](docs/catalog-desktop.png)

## Возможности

- 12 фильмов, поиск по названию/режиссёру и фильтры по шести жанрам.
- «Рандомайз»: до шести случайных фильмов с учётом выбранного жанра и поиска.
- Карточки фильмов с описанием, цитатами и отзывами. Средняя оценка рассчитывается по отзывам пользователей.
- Регистрация, вход и выход; личные публичные стены и общая лента с постраничной загрузкой.
- Создание, редактирование и удаление **своего** ревью: текст, оценка 1–10, необязательная цитата, отметка спойлеров.
- Одно ревью на фильм от пользователя, с возможностью редактирования.
- Адаптивный интерфейс, локальные обложки и системные шрифты. Внешние API и ключи не нужны.

Начальный каталог находится в `database/seed.sql`. Обложки — собственные геометрические иллюстрации, не официальные постеры. Короткие цитаты представлены в русском переводе для демонстрации; формулировки могут отличаться между переводами фильма. Подписок, лайков, внешнего кино-API и панели администратора в первой версии нет.

## Быстрый запуск — Docker Compose

Нужны Git и запущенный Docker с Compose v2 (Windows/macOS: Docker Desktop).

```bash
git clone https://github.com/Ruslan-Berngardt/Oblaka_Krasavchiki.git
cd Oblaka_Krasavchiki
docker compose up --build -d
```

Откройте **http://localhost:8080**. Первый запуск скачает образы, установит зависимости и создаст таблицы с каталогом. Проверьте готовность:

```bash
docker compose ps
docker compose logs -f backend
```

Создайте аккаунт через «Войти» → «Регистрация». Заранее созданных пользователей нет.

Остановка и повторный запуск с сохранением данных:

```bash
docker compose down
docker compose up -d
```

Данные находятся в именованном томе `postgres_data`. **`docker compose down -v` удаляет все данные** — используйте только для намеренного сброса учебной базы.

Порты: интерфейс `8080`, PostgreSQL `5432`. Бэкенд доступен внутри Compose на `backend:3000`; браузер обращается к нему через `/api` на том же `localhost:8080`. Порты опубликованы только на локальном компьютере.

Если порт 5432 занят, скопируйте `.env.example` в `.env` и измените `POSTGRES_PORT=5433`. Для запуска приложения вне Docker также измените порт в `DATABASE_URL`. Если занят 8080, измените левый порт в `frontend.ports` файла `compose.yaml`.

## Запуск без контейнеризации приложения

Нужны **Node.js 22.9+** и **PostgreSQL 17**. Можно запустить только базу контейнером:

```bash
docker compose up -d db
```

Или создайте пользователя и базу в установленном PostgreSQL через pgAdmin/psql, подключившись администратором:

```sql
CREATE USER kadr WITH PASSWORD 'kadr_local_password';
CREATE DATABASE kadr OWNER kadr;
```

Затем в корне проекта:

```bash
cp .env.example .env
npm ci
npm start
```

В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`. При своих настройках PostgreSQL измените `DATABASE_URL` в `.env`.

Адрес в этом режиме — **http://localhost:3000**. Express отдаёт фронтенд и API. `npm run dev` автоматически перезапускает сервер при изменении кода. Не открывайте HTML двойным щелчком: интерфейсу нужен работающий API.

## Архитектура

| Компонент | Реализация | Ответственность |
|---|---|---|
| Фронтенд | HTML, CSS, JavaScript; nginx в Compose | Каталог, формы, модальные окна, стены, запросы fetch |
| Бэкенд | Node.js, Express 5, pg | Авторизация, проверка данных, чтение и запись в PostgreSQL |
| База данных | PostgreSQL, отдельный процесс/контейнер | Пользователи, сессии, каталог, цитаты и отзывы |

В Compose работают **три отдельных сервиса**: `frontend`, `backend`, `db`. nginx отдаёт интерфейс и направляет `/api` бэкенду. Бэкенд выполняет параметризованные SQL-запросы через pg. Фронтенд к БД напрямую не подключается.

При публикации `POST /api/reviews` записывает строку в БД. Открытие стены вызывает `GET /api/reviews?user=ID` и читает сохранённые отзывы. Поэтому обновление страницы не удаляет данные.

| Путь | Содержание |
|---|---|
| `frontend/` | Интерфейс, SVG-обложки, конфигурация nginx |
| `backend/src/app.js` | REST API и обработка ошибок |
| `backend/src/auth.js` | Хеширование паролей и сессии |
| `backend/src/db.js` | Подключение и инициализация базы |
| `backend/src/server.js` | Запуск и корректная остановка |
| `database/schema.sql` | Таблицы, ограничения и индексы |
| `database/seed.sql` | Начальные фильмы, жанры и цитаты |
| `backend/test/integration.test.js` | Интеграционные тесты с PostgreSQL |
| `compose.yaml`, `Dockerfile` | Контейнеры и постоянный том |
| `.github/workflows/ci.yml` | Тесты, сборка и запуск Compose в GitHub Actions |
| `docs/` | Скриншоты, API и материал для защиты |

Инициализация выполняется транзакцией, защищена advisory lock и не дублирует каталог. `ON CONFLICT DO NOTHING` сохраняет существующие записи. Для последующих изменений схемы нужны миграции: `CREATE TABLE IF NOT EXISTS` не изменяет уже созданные столбцы.

## База данных

| Таблица | Назначение |
|---|---|
| users | Имя, уникальный email, хеш пароля |
| sessions | Хеш случайного токена сессии, пользователь, срок действия |
| movies | Название, год, режиссёр, описание, продолжительность, обложка |
| genres | Справочник жанров |
| movie_genres | Связь фильмов с жанрами «многие ко многим» |
| quotes | Цитаты, связанные с фильмами |
| reviews | Автор, фильм, текст, оценка, цитата, спойлеры, даты |

Ограничения БД обеспечивают оценку 1–10, уникальность пары «пользователь + фильм» и принадлежность цитаты выбранному фильму. Удаление пользователя каскадно удаляет его сессии и отзывы.

## Проверка для сдачи

1. Откройте каталог и зарегистрируйте аккаунт.
2. Выберите фильм → «Взять цитату».
3. Укажите оценку, напишите отзыв и нажмите «Опубликовать ревью».
4. Отзыв появится на стене. Обновите страницу — он останется.
5. Выполните `docker compose restart backend` и обновите стену — данные и вход сохранятся.
6. Откройте «Ревью», проверьте публикацию в общей ленте.
7. При необходимости покажите запись в БД:

```bash
docker compose exec db psql -U kadr -d kadr -c "SELECT id, user_id, movie_id, rating, text FROM reviews;"
```

При других именах пользователя/БД подставьте их в команду.

Для отчёта: ссылка на репозиторий, инструкция запуска из README, скриншот опубликованного ревью. В `docs/` также есть скриншоты проверенного приложения: [каталог](docs/catalog-desktop.png), [мобильный вид](docs/catalog-mobile.png), [стена](docs/wall-desktop.png). Стена снята с временным тестовым аккаунтом; он не добавляется в вашу БД автоматически.

Материал для защиты: [docs/defense.md](docs/defense.md). Описание API: [docs/api.md](docs/api.md).

## Автоматические тесты

Нужна отдельная PostgreSQL БД, без SQLite и моков. Для БД в Compose:

```bash
docker compose exec db createdb -U kadr kadr_test
npm ci
```

Linux/macOS:

```bash
TEST_DATABASE_URL=postgresql://kadr:kadr_local_password@localhost:5432/kadr_test npm test
```

PowerShell:

```powershell
$env:TEST_DATABASE_URL="postgresql://kadr:kadr_local_password@localhost:5432/kadr_test"
npm test
```

Используйте свой порт/пароль, если меняли настройки. Тесты создают пользователей с уникальными email и удаляют их после выполнения. Проверяют каталог, регистрацию, валидацию, сохранение в БД, повторный запуск сервера, права доступа, редактирование и выход. `npm run check` проверяет синтаксис.

GitHub Actions запускает тесты с PostgreSQL 17, собирает контейнеры и проверяет доступность интерфейса/API через nginx.

## Настройки и ограничения

Пароли хешируются через scrypt с индивидуальной солью. Сессии действуют 7 дней и хранятся в PostgreSQL; браузер получает HttpOnly/SameSite cookie. SQL использует параметры, интерфейс экранирует пользовательский текст. Изменения принимаются в JSON, CORS не включён, запросы с `Sec-Fetch-Site: cross-site` запрещены. Неудачные попытки авторизации ограничены по IP; за nginx в учебной конфигурации лимит общий для прокси.

Пароль БД по умолчанию предназначен для **локальной лабораторной**. Для публичного размещения замените его, настройте HTTPS, `COOKIE_SECURE=true`, резервное копирование и лимиты с учётом прокси. `.env` не коммитится. Подтверждения email, восстановления пароля и модерации в этой версии нет.

При ошибке подключения: `docker compose ps`, `docker compose logs backend db`. Изменение `POSTGRES_PASSWORD` не меняет пароль в уже существующем томе — измените его в самой БД или используйте прежние настройки.

Справочники: [параметризованные запросы pg](https://node-postgres.com/features/queries), [порядок запуска Compose](https://docs.docker.com/compose/how-tos/startup-order/).
