# Кадр / личная история кино

Лабораторная работа 0 — свой сервис. Команда **Oblaka_Krasavchiki**.

Каталог помогает выбрать фильм, а личная стена позволяет сохранить впечатления, оценку и цитату после просмотра. Сервис будет использоваться в лабораторных 1–3.

![Работающее приложение](docs/screenshot.png)

## Возможности

- 12 фильмов, поиск по названию и режиссёру, фильтры по жанрам.
- Регистрация, вход и выход.
- Создание, редактирование и удаление своего ревью: текст, оценка 1–10, цитата, отметка спойлеров.
- Личные стены пользователей и общая лента отзывов.

## Архитектура

| Часть | Технология | Что делает |
|---|---|---|
| Фронтенд | HTML, CSS, JavaScript (`frontend/`) | Каталог, формы, запросы к бэкенду по `/api` |
| Бэкенд | Node.js, Express 5, pg (`backend/`) | Авторизация, валидация, запись в БД и чтение из неё |
| База данных | PostgreSQL | Отдельный сетевой сервис: пользователи, сессии, фильмы, отзывы |

Браузер обращается к бэкенду, бэкенд выполняет SQL-запросы к PostgreSQL. Фронтенд к БД напрямую не подключается. В этой лабораторной статику фронтенда отдаёт сам Express.

Таблицы: `users`, `sessions`, `movies`, `genres`, `movie_genres`, `quotes`, `reviews`. При первом запуске бэкенд сам создаёт их по `database/schema.sql` и наполняет каталог из `database/seed.sql`.

## Требования

- Git
- Node.js 22.9 или новее
- PostgreSQL 17

## Запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/Ruslan-Berngardt/Oblaka_Krasavchiki.git
cd Oblaka_Krasavchiki/Lab0
```

### 2. Установить и запустить PostgreSQL

**macOS (Homebrew):**
```bash
brew install postgresql@17
brew services start postgresql@17
echo 'export PATH="/opt/homebrew/opt/postgresql@17/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
pg_isready
```
Последняя команда должна вернуть `accepting connections`.

**Linux / Windows:** установите PostgreSQL 17 с https://www.postgresql.org/download/ и запустите службу.

### 3. Создать пользователя и базу данных

Подключитесь к PostgreSQL под пользователем с правами создания ролей и баз данных:

```bash
psql -U POSTGRES_ADMIN -d postgres
```

Замените `POSTGRES_ADMIN` на имя вашего администратора PostgreSQL.

В открывшейся консоли выполните:

```sql
CREATE USER app_user;
\password app_user
CREATE DATABASE app_db OWNER app_user;
```

Команда `\password` предложит задать пароль интерактивно. Выберите собственный пароль.

`app_user` и `app_db` — условные имена пользователя приложения и базы. Их можно заменить своими.

Для выхода выполните:

```text
\q
```

### 4. Настроить подключение

Приложению нужно сообщить, к какой базе PostgreSQL подключаться. Для этого запишите данные **пользователя приложения и базы из шага 3** в локальный файл `.env`. Имя администратора PostgreSQL в эту строку подставлять не нужно.

Все команды ниже выполняйте в обычном терминале, находясь в папке `Lab0`. Если ещё открыта консоль PostgreSQL с приглашением `postgres=#`, сначала выйдите командой `\q`.

#### 4.1. Создать файл настроек

Если файла `.env` ещё нет, скопируйте пример:

**macOS / Linux:**

```bash
cp .env.example .env
```

**Windows PowerShell:**

```powershell
Copy-Item .env.example .env
```

Получится отдельный файл `Lab0/.env`. Если он уже существует и настроен, повторно копировать пример не нужно: это перезапишет ваши настройки. Редактировать нужно именно `.env`, а не `.env.example`.

#### 4.2. Открыть файл в редакторе

На **macOS** выполните:

```bash
open -e .env
```

Файл откроется в TextEdit. Сохраняйте его как обычный текст, без форматирования и без добавления расширения `.txt`.

На **Windows** можно открыть его в Блокноте:

```powershell
notepad .env
```

Также на любой системе можно открыть папку `Lab0` в VS Code и выбрать файл `.env` в списке файлов. Если ищете его через Finder на Mac, нажмите **⌘ + Shift + .**, чтобы показать скрытые файлы.

#### 4.3. Изменить строку подключения

Найдите в файле строку, которая начинается с `DATABASE_URL=`, и замените её своими данными. Общий формат:

```text
DATABASE_URL=postgresql://DB_USER:DB_PASSWORD@DB_HOST:DB_PORT/DB_NAME
```

Это **шаблон**: обозначения `DB_USER`, `DB_PASSWORD` и остальные нужно заменить конкретными значениями, а не оставлять в файле буквально.

| Обозначение | Что вставить |
|---|---|
| `DB_USER` | Имя пользователя приложения, созданного в шаге 3 |
| `DB_PASSWORD` | Пароль, который вы задали этому пользователю командой `\password` |
| `DB_HOST` | `localhost`, если PostgreSQL работает на вашем компьютере |
| `DB_PORT` | Порт PostgreSQL, обычно `5432` |
| `DB_NAME` | Имя базы, созданной в шаге 3 |

Если в шаге 3 вы оставили имена `app_user` и `app_db`, строка будет выглядеть так:

```text
DATABASE_URL=postgresql://app_user:YOUR_PASSWORD@localhost:5432/app_db
```

Здесь **`YOUR_PASSWORD` обязательно замените собственным паролем**. Если вы выбрали другие имена пользователя или базы, замените также `app_user` и `app_db`.

Если пароль содержит специальные символы URL, их нужно записать в URL-кодировке: например, `@` как `%40`, `#` как `%23`, `%` как `%25`. Это меняет только запись пароля в строке подключения, а не сам пароль в PostgreSQL.

Остальные строки файла оставьте. Для локального запуска через `npm start` приложение использует `DATABASE_URL`; отдельные переменные `POSTGRES_*`, если они есть в примере, не заменяют данные в этой строке.

> **Важно:** строку `DATABASE_URL=...` нужно вписать в открытый файл `.env`, а не выполнять как команду в терминале. Ввод строки в терминале не изменяет содержимое файла.

#### 4.4. Сохранить настройки

Нажмите **⌘ + S** на Mac или **Ctrl + S** на Windows/Linux. Убедитесь, что имя файла осталось `.env`, и в нём есть только одна строка `DATABASE_URL=` с вашими данными.

Файл `.env` исключён из Git. Не публикуйте его содержимое с реальным паролем в README, коммитах или скриншотах.

Вернитесь в терминал и переходите к шагу 5: `npm ci`, затем `npm start`. Если сервер уже был запущен, остановите его через **Ctrl + C** и запустите снова: новые настройки читаются при запуске процесса.

### 5. Установить зависимости и запустить

```bash
npm ci
npm start
```

### 6. Открыть приложение

**http://localhost:3000**

Не открывайте HTML двойным щелчком: интерфейсу нужен работающий бэкенд.

## Настройки

| Переменная | Описание |
|---|---|
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `PORT` | Порт бэкенда (по умолчанию 3000) |

## Проверка работоспособности

1. Открыть http://localhost:3000.
2. Нажать «Войти» → «Регистрация» и создать аккаунт.
3. Выбрать фильм, поставить оценку, написать отзыв, нажать «Опубликовать ревью».
4. Отзыв появится на стене пользователя.
5. Перезагрузить страницу. Отзыв на месте, значит он сохранён в PostgreSQL.
6. При желании посмотреть запись прямо в базе:
   ```bash
   psql -U kadr -d kadr -h localhost -c "SELECT id, user_id, movie_id, rating, text FROM reviews;"
   ```

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `npm: command not found` | Установить Node.js: `brew install node` |
| Приложение падает при старте | Проверить, что PostgreSQL запущен: `pg_isready` |
| Ошибка авторизации в БД | Проверить, что логин, пароль и имя базы в `DATABASE_URL` совпадают с созданными в шаге 3 |
| Порт 3000 занят | Указать другой `PORT` в `.env` |
