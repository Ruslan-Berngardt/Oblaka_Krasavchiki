# Кадр / личная история кино

Лабораторная 0 команды **Oblaka_Krasavchiki**. Пользователь выбирает фильм из каталога, ставит оценку, пишет ревью и добавляет цитату. Публикации появляются на его стене и в общей ленте, сохраняются в PostgreSQL и остаются после обновления страницы.

![Каталог сервиса](docs/catalog-desktop.png)

## Что умеет сервис

- Каталог из 12 фильмов, поиск по названию/режиссёру, фильтры по жанрам и случайная подборка.
- Регистрация, вход и выход; публичные личные стены и общая лента.
- Создание, редактирование и удаление своего ревью: оценка 1–10, текст, цитата и отметка спойлеров.
- Одно ревью на фильм от пользователя с возможностью редактирования.

## Что потребуется

- Docker Desktop с Docker Compose v2. Для Linux также подойдёт Docker Engine с Compose v2.
- Интернет для первого скачивания образов и зависимостей.
- Свободный локальный порт 8080. Если он занят, ниже описана смена порта.

Node.js, npm и PostgreSQL отдельно устанавливать **не нужно**: они работают внутри контейнеров. Команды `npm ci`, `npm start`, `CREATE USER`, `CREATE DATABASE` и редактирование `DATABASE_URL` для этого способа не нужны. Если Node.js/npm отсутствуют на компьютере, Docker-запуск всё равно работает.

## Полная инструкция запуска

### 1. Установить и запустить Docker Desktop

**macOS:** откройте [официальную инструкцию](https://docs.docker.com/desktop/setup/install/mac-install/), выберите установщик для Apple silicon (M1/M2/M3 и новее) или Intel. Тип процессора указан в « → Об этом Mac». Откройте `.dmg`, перенесите Docker в «Программы» и запустите Docker Desktop. Завершите первоначальную настройку и дождитесь готовности Docker Engine.

**Windows:** установите [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/), выполните предложенные установщиком требования WSL 2/виртуализации и перезагрузку, если она потребуется. Запустите Docker Desktop в режиме Linux-контейнеров.

**Linux:** установите [Docker Engine](https://docs.docker.com/engine/install/) и [плагин Compose](https://docs.docker.com/compose/install/linux/), запустите Docker и настройте доступ текущего пользователя к нему согласно инструкции установки.

Откройте обычный терминал: на Mac — приложение «Терминал», на Windows — PowerShell. Проверьте по очереди:

```bash
docker version
docker compose version
```

Первая команда должна показать **Client и Server**, вторая — версию Compose v2. Если получаете `Cannot connect to the Docker daemon`, Docker Desktop ещё не запущен или Engine не готов. Если `docker: command not found`, завершите установку и заново откройте терминал. Не переходите дальше, пока команды не работают.

### 2. Подготовиться, если раньше запускали приложение другим способом

- Если в терминале работает `npm start`, нажмите **Control + C**. Если видите приглашение `postgres=#`, введите `\q` и нажмите Enter. Это разные действия: первое останавливает приложение, второе выходит из psql.
- PostgreSQL из Homebrew можно оставить работающим: **новая конфигурация не публикует порт БД 5432 на компьютер**, поэтому конфликта с ним нет. При желании остановите его командой `brew services stop postgresql@17`. Локальные базы при этом не удаляются.
- Если старый Docker-сервис занимает 8080, остановите его через Docker Desktop → Containers → нужный проект → Stop. Для старого проекта из нашей ZIP-инструкции можно использовать `docker stop oblaka_krasavchiki-main-frontend-1`; сначала убедитесь, что такое имя есть в `docker ps`. Базу и том не удаляйте. Либо выберите другой порт в шаге 5.
- Ранее скачанный архив со снимком коммита не обновляется сам. Для новой инструкции нужен **свежий main**, а не ссылка на старую версию из переписки.

### 3. Скачать актуальный проект

Выберите **один** вариант.

**Вариант A — ZIP, без установки Git:**

1. Откройте [репозиторий](https://github.com/Ruslan-Berngardt/Oblaka_Krasavchiki), убедитесь, что выбрана ветка `main`.
2. Нажмите **Code → Download ZIP** или [скачайте main.zip](https://github.com/Ruslan-Berngardt/Oblaka_Krasavchiki/archive/refs/heads/main.zip).
3. Распакуйте архив. Внутри папки `Oblaka_Krasavchiki-main` найдите **Lab0**.
4. На Mac откройте терминал, напишите `cd` с пробелом, перетащите папку **Lab0** из Finder в окно терминала и нажмите Enter. На Windows откройте Lab0 в Проводнике, в адресной строке введите `powershell` и нажмите Enter.

На Mac путь обычно такой, но имя/расположение распакованной папки может отличаться:

```bash
cd ~/Downloads/Oblaka_Krasavchiki-main/Lab0
```

**Вариант B — Git, если он установлен:**

```bash
git clone https://github.com/Ruslan-Berngardt/Oblaka_Krasavchiki.git
cd Oblaka_Krasavchiki/Lab0
```

Если это уже существующая Git-копия, перейдите в корень репозитория, выполните `git pull --ff-only`, затем `cd Lab0`. Если Git сообщает о ваших локальных изменениях, сохраните их отдельно и разберитесь с ними; не удаляйте их принудительно ради обновления.

Проверьте содержимое папки командой `ls` (в PowerShell — `Get-ChildItem`). Должны быть **compose.yaml, Dockerfile, scripts, frontend, backend, database**. Все дальнейшие команды выполняются именно в этой `Lab0`, а не в корне репозитория и не в консоли psql.

### 4. Создать локальные настройки Docker

Вместо общего пароля из README используется случайный пароль, который скрипт создаёт на вашем компьютере.

**macOS / Linux:**

```bash
sh scripts/setup-docker-env.sh
```

**Windows PowerShell:**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-docker-env.ps1
```

Эта команда создаёт **Lab0/.env.docker** с настройками:

| Переменная | Назначение |
|---|---|
| `POSTGRES_USER` | Имя роли, создаваемой образом PostgreSQL при первом запуске |
| `POSTGRES_DB` | Имя базы, создаваемой при первом запуске |
| `POSTGRES_PASSWORD` | Случайный пароль, созданный скриптом; его не нужно придумывать или вводить в psql |
| `HOST_PORT` | Порт сайта на вашем компьютере, изначально 8080 |

Пароль не выводится в терминал, не хранится в README и не коммитится. Запуск скрипта повторно **не перезаписывает** существующий `.env.docker`. Храните этот файл вместе с локальным проектом: при его потере новый пароль не изменит пароль в уже созданной БД автоматически.

**В обычном случае ничего редактировать не нужно.** Строку `DATABASE_URL` Compose собирает сам с адресом `db:5432`. Ранее настроенный `.env` для ручного `npm start` здесь не используется: в командах мы явно указываем `--env-file .env.docker`.

Это локальный учебный стек. Роль из `POSTGRES_USER` создаётся официальным образом с административными правами; для публичной эксплуатации нужно отдельно настроить ограниченную роль приложения и прочие меры. Администратора сайта с общим логином/паролем нет: аккаунт сайта вы создадите через регистрацию.

### 5. При необходимости изменить порт сайта

Если 8080 свободен, переходите к шагу 6.

Если хотите использовать другой порт, откройте **.env.docker**. На Mac:

```bash
open -e .env.docker
```

На Windows:

```powershell
notepad .env.docker
```

Можно открыть файл в VS Code. В Finder скрытые файлы показываются сочетанием **⌘ + Shift + .**.

Замените только строку `HOST_PORT=8080` на `HOST_PORT=8081`, сохраните обычный текст через **⌘ + S / Ctrl + S**. Не добавляйте расширение `.txt`. Эти строки записываются **в файл**, а не выполняются в терминале. Остальные значения, особенно пароль уже существующей базы, менять не нужно.

### 6. Проверить конфигурацию и запустить

В той же папке `Lab0` выполните по очереди:

```bash
docker compose --env-file .env.docker config --quiet
docker compose --env-file .env.docker up --build -d --wait
```

Первая команда проверяет конфигурацию; при успехе ничего не печатает. Не публикуйте вывод обычного `docker compose config` без `--quiet`: в нём могут оказаться данные подключения.

Вторая скачает базовые образы, установит npm-зависимости **внутри образа**, соберёт приложение и запустит три сервиса. Первый запуск может занять несколько минут; для него нужен интернет. `--build` включает сборку, `-d` оставляет контейнеры в фоне, `--wait` ждёт их готовности. После завершения вернётся строка ввода терминала.

Имя Compose-проекта закреплено в конфигурации как **kadr-lab0**, поэтому оно не меняется при переносе папки или скачивании ZIP в другое место. Добавлять `-p` к стандартным командам больше не требуется. Это отдельное имя для новой конфигурации: старые проекты `kadr` и `oblaka_krasavchiki-main` и их тома автоматически не подключаются. Для повторного запуска новой конфигурации сохраняйте её `.env.docker`.

### 7. Проверить состояние и открыть сайт

```bash
docker compose --env-file .env.docker ps
```

Должны быть три работающих сервиса:

| Сервис | Назначение | Ожидаемое состояние |
|---|---|---|
| `db` | PostgreSQL и постоянные данные | Up / healthy |
| `backend` | API, авторизация, чтение и запись в БД | Up / healthy |
| `frontend` | nginx, файлы интерфейса и пересылка `/api` | Up / healthy |

Откройте **http://localhost:8080**. Если меняли `HOST_PORT` на 8081, откройте **http://localhost:8081**.

Важно: адрес Docker-версии — **8080**, а не 3000; HTML-файл двойным щелчком не открывайте.

В браузере также можно проверить **http://localhost:8080/api/health**. Ответ при нормальной работе:

```json
{"status":"ok","database":"connected"}
```

### 8. Создать аккаунт и проверить сохранение

1. Нажмите «Войти» → «Регистрация».
2. Введите свои имя, email и пароль **аккаунта сайта**. Это не пароль PostgreSQL.
3. Выберите фильм, оценку, цитату и напишите ревью.
4. Опубликуйте его и обновите страницу стены — отзыв останется.
5. Проверьте общую ленту «Ревью».
6. При желании перезапустите сервер и проверьте стену снова:

   ```bash
   docker compose --env-file .env.docker restart backend
   ```

Docker использует **отдельную БД внутри контейнера**. Пользователи и отзывы из PostgreSQL, установленного через Homebrew, автоматически туда не переносятся. Отсутствие этих аккаунтов в новой Docker-базе не означает их удаление. У каждого участника команды при локальном запуске своя БД.

## Ежедневные команды: остановка и повторный запуск

Docker Desktop должен работать. Откройте терминал в той же `Lab0` с вашим `.env.docker`.

**Остановить на сегодня, сохранив данные:**

```bash
docker compose --env-file .env.docker stop
```

**Включить существующие остановленные контейнеры:**

```bash
docker compose --env-file .env.docker start
```

**Проверить состояние:**

```bash
docker compose --env-file .env.docker ps
```

**Посмотреть логи:**

```bash
docker compose --env-file .env.docker logs --tail=60
docker compose --env-file .env.docker logs -f backend
```

Ctrl+C в просмотре логов завершает только просмотр, контейнеры продолжают работать.

**Удалить контейнеры и сеть, сохранив БД:**

```bash
docker compose --env-file .env.docker down
```

**Создать/включить их снова после down:**

```bash
docker compose --env-file .env.docker up -d --wait
```

`start` работает только с уже существующими контейнерами. После `down` нужен `up`.

**Намеренно очистить всю Docker-базу:**

```bash
docker compose --env-file .env.docker down -v
```

**Последняя команда удаляет аккаунты и отзывы. Для обычной остановки она не нужна.** Данные живут в именованном томе `kadr-lab0_postgres_data`, а не в SQL-файлах репозитория.

## Обновление кода

Для Git-копии из корня репозитория:

```bash
git pull --ff-only
cd Lab0
docker compose --env-file .env.docker up --build -d --wait
```

Для ZIP скачайте свежий main и сохраните свой `.env.docker` в `Lab0` обновлённой копии (он содержит пароль; не отправляйте его другим). Используйте тот же Docker Engine и имя проекта. Затем выполните команду сборки выше. Обычные stop/start или restart не пересобирают изменённый код.

Если раньше запускали первоначальную версию из истории проекта, **не заменяйте её пароль новым** в надежде получить старые данные. Наши старые варианты могли использовать другие имена проектов и томов. Данные можно перенести отдельно через pg_dump/восстановление; для открытия новой версии перенос необязателен.

## Если что-то не работает

| Сообщение или симптом | Что сделать |
|---|---|
| `docker: command not found` | Установить Docker Desktop и заново открыть терминал |
| `Cannot connect to the Docker daemon` | Открыть Docker Desktop, дождаться запуска Engine, повторить `docker version` |
| `cd: no such file or directory: Lab0` | Перейти в свежую распакованную копию; на Mac перетащить её папку Lab0 после `cd ` |
| Нет `compose.yaml` / `no configuration file provided` | Вы находитесь не в Lab0 либо скачана старая версия. Проверить `ls` / `Get-ChildItem` |
| Нет `.env.docker` / не задан `POSTGRES_PASSWORD` | Выполнить шаг 4, затем использовать `--env-file .env.docker` во всех командах |
| `unknown flag: --wait` | Обновить Docker Desktop / Compose v2 и проверить `docker compose version` |
| Порт 8080 занят / `address already in use` | Остановить старый проект в Docker Desktop либо задать другой HOST_PORT, затем снова выполнить `up -d --wait` |
| Ошибка скачивания образа, DNS или соединения | Проверить доступ Docker к интернету и настройки сети/прокси Docker Desktop; повторить команду сборки |
| Контейнер `unhealthy`, завершился или сайт не открывается | Выполнить `ps -a`, затем `logs --tail=100 db backend frontend` с тем же префиксом Compose |
| БД сообщает неверный пароль после смены настроек | Вернуть прежний `.env.docker`: пароль существующего тома не меняется от редактирования файла |
| После запуска не видно старых отзывов | Проверить, не использовались ли Homebrew-БД, другой Docker Engine, имя проекта или том. Не удалять тома для исправления |
| После правки кода ничего не поменялось | Выполнить `up --build -d --wait`, затем обновить страницу браузера |

Команды диагностики целиком:

```bash
docker compose --env-file .env.docker ps -a
docker compose --env-file .env.docker logs --tail=100 db backend frontend
```

Если нужен совет, отправьте сообщение об ошибке и логи. Не отправляйте содержимое `.env.docker`, пароль и полный вывод конфигурации с секретами.

## Как части взаимодействуют

| Часть | Технология и путь | Что делает |
|---|---|---|
| Фронтенд | HTML, CSS, JS в `frontend/`; nginx в контейнере | Отдаёт страницу браузеру, проксирует `/api` на backend:3000 |
| Бэкенд | Node.js, Express, pg в `backend/` | Определяет пользователя, проверяет ввод, выполняет SQL |
| База | PostgreSQL в `db` | Хранит пользователей, сессии, фильмы и ревью на постоянном томе |

JavaScript интерфейса работает в браузере. Браузер обращается к localhost:8080; nginx направляет `/api` бэкенду. Сервер обращается к PostgreSQL по `db:5432`. База не опубликована на порт компьютера; для просмотра записей используйте Docker exec.

```bash
docker compose --env-file .env.docker exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT id, user_id, movie_id, rating, text FROM reviews;"'
```

Команда выше для macOS/Linux. На Windows можно открыть PostgreSQL через `docker compose --env-file .env.docker exec db psql -U kadr -d kadr`, затем выполнить `SELECT id, user_id, movie_id, rating, text FROM reviews;` и выйти через `\q`. Имена `kadr` — исходные имена пользователя и БД; при своих настройках замените их.

Фронтенд и БД подключены к разным сетям; бэкенд подключён к обеим. Перед запуском бэкенда Compose ждёт готовности БД, перед запуском nginx — готовности бэкенда. Проверки healthcheck есть у всех трёх сервисов; политика restart настроена на восстановление после завершения процесса, но ручная команда stop не отменяется автоматикой.

`database/schema.sql` создаёт таблицы, `seed.sql` добавляет каталог. Они выполняются сервером при старте идемпотентно и не являются миграциями схемы. Живые отзывы лежат в PostgreSQL.

## Связь с лабораторными

Docker добавлен для удобного воспроизводимого запуска сервиса из Лабы 0. Это также заготовка для дальнейшей работы. Здесь нет полного сравнения плохого и хорошего образов, замеров кеша/размера, HTTPS, балансировки двух бэкендов, Trivy, публикации релизных образов, постоянного деплоя или rollback. Эти задания оформляются отдельно в следующих лабораторных.

Ручной способ с установкой PostgreSQL и настройкой DATABASE_URL сохранён в [docs/manual-start.md](docs/manual-start.md). Не смешивайте команды двух способов: для обычного Docker-запуска достаточно шагов этой страницы.
