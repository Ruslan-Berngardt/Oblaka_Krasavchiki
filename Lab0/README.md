# МЕГА ПРОЕКТ "КАДР"

Наша команда собралась реализовать лабораторные работы, и мы подумали о том, что можно немножко добавить хайпа и сделать некую **соцесеть по фильмам**. Пользователь выбирает фильм из каталога, ставит оценку, пишет ревью и добавляет цитату. Публикации появляются на его стене и в общей ленте, сохраняются в PostgreSQL и остаются после обновления страницы.

![Каталог сервиса](docs/catalog-desktop.png)

## В чем наш сервис может погеройствовать:

В наличии каталога из 12 фильмов, поиску по названию/режиссёру, фильтрам по жанрам и рандомайзеру. В данной соцсети можно регистрироваться делать посты с отзывами и видеть их на общей ленте

## Полная инструкция запуска (ВСЕ ДЕЛАТЬ АККУРАТНЕНЬКО ПО ПУНКТАМ)

### 1. Установить и запустить Docker Desktop

Нужно установить Docker Desktop с Docker Compose v2. Для Linux также подойдёт Docker Engine с Compose v2

**macOS:** откройте [официальную инструкцию](https://docs.docker.com/desktop/setup/install/mac-install/). Все предельно интуитивно понятно (не как с node.js, как мы пытались сделать до...)

**Windows:** установите [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/), выполните предложенные установщиком требования WSL 2/виртуализации и перезагрузку, если она потребуется. Запустите Docker Desktop в режиме Linux-контейнеров.

**Linux:** установите [Docker Engine](https://docs.docker.com/engine/install/) и [плагин Compose](https://docs.docker.com/compose/install/linux/), запустите Docker и настройте доступ текущего пользователя к нему согласно инструкции установки.

Откройте обычный терминал: на Mac — приложение «Терминал», на Windows — PowerShell. НО некоторым из нашей Тимы было проще VS Code. Проверьте по очереди:

```bash
docker version
docker compose version
```

Тут проблемы могут быть только в том случае, если докер не установлен. Надо убедиться, что все есть и тогда будет шик

### 2. Скачать актуальный проект

Выберите **один** вариант.

**Вариант A — ZIP, без установки Git:**

1. Откройте [репозиторий](https://github.com/Ruslan-Berngardt/Oblaka_Krasavchiki), убедитесь, что выбрана ветка `main`.
2. Нажмите **Code → Download ZIP** или [скачайте main.zip](https://github.com/Ruslan-Berngardt/Oblaka_Krasavchiki/archive/refs/heads/main.zip).
3. Распакуйте архив. Внутри папки `Oblaka_Krasavchiki-main` найдите **Lab0**.
4. На Mac откройте терминал, напишите `cd` с пробелом, перетащите папку **Lab0** из Finder в окно терминала и нажмите Enter. На Windows откройте Lab0 в Проводнике, в адресной строке введите `powershell` и нажмите Enter.

Ну способ странноват, но по идее так сделать тоже можно, НО мы все делали другим способом

На Mac путь обычно такой, но имя/расположение распакованной папки может отличаться:

**Вариант B — Git, если он установлен:**

```bash
git clone https://github.com/Ruslan-Berngardt/Oblaka_Krasavchiki.git
cd Oblaka_Krasavchiki/Lab0
```

### 3. Создать локальные настройки Docker

**macOS / Linux:**

```bash
sh scripts/setup-docker-env.sh
```

**Windows PowerShell:**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-docker-env.ps1
```

Эта команда создаёт **Lab0/.env.docker** с настройками:

| Переменная | Назначение |
|---|---|
| `POSTGRES_USER` | Имя роли, создаваемой образом PostgreSQL при первом запуске |
| `POSTGRES_DB` | Имя базы, создаваемой при первом запуске |
| `POSTGRES_PASSWORD` | Случайный пароль, созданный скриптом; его не нужно придумывать или вводить в psql |
| `HOST_PORT` | Порт сайта на вашем компьютере, изначально 8080 |

### 4. Проверить конфигурацию и запустить

В той же папке `Lab0` выполните по очереди:

```bash
docker compose --env-file .env.docker config --quiet
docker compose --env-file .env.docker up --build -d --wait
```

Первая команда проверяет конфигурацию; при успехе ничего не печатает.

Вторая скачает базовые образы, установит npm-зависимости **внутри образа**, соберёт приложение и запустит три сервиса. Первый запуск может занять несколько минут; для него нужен интернет. `--build` включает сборку, `-d` оставляет контейнеры в фоне, `--wait` ждёт их готовности. После завершения вернётся строка ввода терминала.

### 6. Проверить состояние и открыть сайт

```bash
docker compose --env-file .env.docker ps
```

Откройте **http://localhost:8080**.

ОДИН ИЗ МИНУС ВАЙБИКОВ: Docker использует **отдельную БД внутри контейнера**. Пользователи и отзывы из PostgreSQL, установленного через Homebrew, автоматически туда не переносятся. У каждого участника команды при локальном запуске своя БД.

**Остановить на мегасервер, сохранив данные можно таким образом:**

```bash
docker compose --env-file .env.docker stop
```

**Включить существующие остановленные контейнеры:**

```bash
docker compose --env-file .env.docker start
```

## Как части взаимодействуют

| Часть | Что делает |
|---|---|---|
| Фронтенд |Отдаёт страницу браузеру, проксирует `/api` на backend:3000 |
| Бэкенд | Определяет пользователя, проверяет ввод, выполняет SQL |
| База | Хранит пользователей, сессии, фильмы и ревью на постоянном томе |

JavaScript интерфейса работает в браузере. Браузер обращается к localhost:8080; далее направляет `/api` бэкенду. Сервер обращается к PostgreSQL. База не опубликована на порт компьютера; для просмотра записей используйте Docker exec.

Фронтенд и БД подключены к разным сетям; бэкенд подключён к обеим. Перед запуском бэкенда Compose ждёт готовности БД, перед запуском nginx — готовности бэкенда. Проверки healthcheck есть у всех трёх сервисов; политика restart настроена на восстановление после завершения процесса, но ручная команда stop не отменяется автоматикой.

`database/schema.sql` создаёт таблицы, `seed.sql` добавляет каталог. Они выполняются сервером при старте идемпотентно и не являются миграциями схемы. Живые отзывы лежат в PostgreSQL.

## Структура нашего **КАДРА**

| Путь | Содержание |
|---|---|
| `compose.yaml` | Три сервиса, внутренние сети, порт сайта и постоянный том |
| `Dockerfile` | Сборка бэкенда, установка зависимостей, запуск под пользователем node |
| `frontend/Dockerfile`, `frontend/nginx.conf` | Сборка фронтенда и маршрутизация запросов |
| `scripts/setup-docker-env.sh`, `.ps1` | Создание локального случайного пароля |
| `scripts/smoke.mjs` | Приёмочная проверка API для временной CI-базы |
| `backend/`, `frontend/`, `database/` | Исходники приложения и SQL |
| `docs/manual-start.md`, `.env.example` | Альтернативный ручной запуск без Docker |
| `../.github/workflows/docker.yml` | Проверка синтаксиса, сборка, запуск, публикация отзыва, пересоздание контейнеров и проверка сохранности данных |
